3  总体设计
3.1  设计目标、输入输出与原则
本系统面向在线视频课程学习过程中的导学支持需求，目标是构建一个能够结合课程视频内容、学习进度和学习者提问状态的本地化智能助教平台。系统以课程视频为主要学习载体，通过离线多模态知识构建和在线检索增强问答相结合的方式，为学习者提供视频播放、随堂测验、上下文感知问答和补充资料扩展等功能，从而形成“观看课程、触发测验、即时反馈、继续追问”的闭环学习过程。

从功能目标看，系统需要完成三类任务：第一，对课程视频进行离线处理，提取语音字幕、画面文字、公式图表和知识点等信息，并生成可检索的多模态知识片段；第二，在学习者观看视频时，根据视频名称、当前播放时间和历史对话等上下文信息，提供与当前学习进度相关的问答服务；第三，在关键知识点位置触发随堂测验，并根据学习者作答结果返回正误判定和知识点反馈。从工程目标看，系统需要兼顾本地部署、模块解耦、增量处理和响应稳定性，避免将耗时较高的转写、视觉解析和向量化任务放入在线交互链路。

从输入输出关系看，系统输入主要分为离线构建输入和在线交互输入两类。离线构建输入包括课程视频文件、已有补充资料以及模型路径、数据库路径、接口密钥等配置参数，系统根据这些输入生成字幕转写结果、关键帧视觉描述、多模态时间线、知识点、题库数据、补充资料文档和向量索引。在线交互输入包括学习者问题、当前视频名称、当前播放时间、历史对话、题目编号和用户答案等，系统根据这些输入返回视频资源信息、题目内容、智能问答结果、引用依据、答案正误判定和知识点反馈。通过明确输入与输出边界，系统能够将离线知识加工任务与在线学习服务任务分离，使各模块的数据流向和职责更加清晰。

为实现上述目标，系统遵循以下设计原则：
（1）分层解耦原则：将用户界面、后端服务、离线知识构建、数据存储与检索功能划分为相对独立的层次，使各模块能够分别开发、调试和替换。
（2）离线在线分流原则：将视频转写、关键帧解析、知识点提炼、题库生成和向量化入库等计算密集型任务放在离线阶段完成，在线阶段主要负责请求接收、上下文组织、检索编排和结果返回。
（3）多模态融合原则：不仅利用视频语音转写文本，还提取关键帧中的文字、公式、图表和场景语义，并通过统一时间轴将语音信息与视觉信息对齐，提升知识片段对课程内容的表达完整性。
（4）上下文感知原则：在线问答不只接收学习者问题文本，还结合当前视频、播放时间、局部时间窗内容、历史对话和向量检索结果生成回答，使回答更贴近学习者正在观看的知识点。
（5）可扩展原则：系统支持新增课程视频后的增量处理、补充资料的增量入库、检索组件和大模型接口的替换，为后续扩展更多课程资源和教学场景提供基础。

（1）前端交互层。该层采用Vue3实现，面向学习者提供视频播放、课程切换、随堂测验弹窗、智能问答窗口和历史消息展示等功能。前端在用户学习过程中负责采集交互输入，包括当前视频名称、当前播放时间、学习者问题、测验作答结果和最近历史对话，并将其封装为请求发送至后端服务。前端接收的输出包括视频列表、题目时间戳、题目内容、问答结果、引用依据和测验反馈等。

（2）后端服务层。该层采用Python和FastAPI实现，是前端交互与模型、数据库、检索组件之间的调度中心。后端主要提供视频资源接口、题目查询接口、答题评估接口、RAG问答接口、视频重建接口和流水线执行接口。其输入为前端提交的结构化请求，输出为面向页面展示的结构化结果，例如题目对象、正误判定、知识点反馈、回答正文和检索来源。后端服务本身不进行模型训练，而是调用外部大模型接口、向量检索组件和本地数据库完成推理与结果组织。

（3）离线知识构建层。该层由一组本地流水线脚本构成，负责将原始课程视频转换为可用于教学问答和随堂测验的数据资源。离线流程以videos目录中的视频文件为主要输入，依次完成字幕转写与纠错、关键帧提取与VLM解析、多模态时间线融合、知识点提炼与题库入库、字幕/视觉内容向量化入库、网络补充资料生成、补充资料向量化入库七个阶段。该层的输出包括字幕文件、多模态时间线文件、关键帧与视觉描述、知识点、题目数据、补充资料文档和向量索引。

（4）数据存储与检索层。该层由SQLite、Chroma向量库和补充资料文档库共同组成。SQLite主要存储结构化数据，包括课程视频名称、题目、选项、标准答案、知识点、题目触发时间戳和反馈所需字段；Chroma主要存储课程字幕、多模态片段和补充资料的向量表示及其元数据，用于根据学习者问题进行语义召回；补充资料文档库保存由Web知识搜集Agent生成的Markdown资料，为课程内容提供扩展性知识来源。

系统整体不涉及新模型训练和参数微调。语音识别、视觉理解、知识点提炼、问答生成和答题反馈均通过已有模型或OpenAI兼容接口完成，本文重点在于多模态课程知识构建、检索增强问答流程设计和在线学习交互系统实现。

为明确系统各模块边界，本文进一步将系统输入输出划分为离线构建输入输出和在线交互输入输出两类。

离线构建阶段的输入主要包括课程视频文件、已有补充资料和系统配置参数。其中课程视频文件用于提取音频字幕和画面信息；已有补充资料用于扩展课程知识范围；系统配置参数包括模型名称、路径、接口密钥、数据库路径和向量库路径等。离线构建阶段的输出主要包括以下几类：第一，字幕转写结果及纠错后的文本片段；第二，关键帧图像及其视觉语义描述；第三，按照时间轴对齐后的多模态课程片段；第四，知识点列表、随堂测验题目、选项、答案和解析；第五，写入Chroma的向量索引及其元数据；第六，Web知识搜集Agent生成的补充资料文档。

在线交互阶段的输入来自学习者和前端页面状态，主要包括学习者问题question、当前视频名video_name、当前播放时间current_time、历史对话history、题目编号question_id和用户答案user_answer等。在线交互阶段的输出主要包括三类：第一，课程资源相关数据，如视频列表、题目时间戳和指定时间点的题目内容；第二，智能问答结果，如回答正文、引用片段、来源说明和扩展解释；第三，测验评估结果，如答案正误、标准答案、知识点反馈和继续学习提示。

系统数据流分为离线知识构建流程和在线学习交互流程，两条流程通过SQLite数据库和Chroma向量库衔接。

离线知识构建流程以课程视频为起点。系统首先调用语音识别组件对视频音频进行转写，并对字幕文本进行纠错和规范化处理；随后通过OpenCV抽取关键帧，并调用视觉大模型解析画面中的文字、公式、图表和场景信息；接着将字幕片段和视觉片段按照时间戳进行对齐，形成多模态时间线；然后基于多模态课程片段提炼知识点并生成随堂测验题目，将题目、选项、答案、知识点和触发时间写入SQLite；最后将课程片段和补充资料转化为向量表示并写入Chroma，为在线问答提供语义检索基础。

在线学习交互流程以学习者操作为起点。用户打开前端页面后，系统首先通过视频资源接口加载可学习课程列表，并根据所选课程读取题目时间戳。当视频播放到关键知识点附近时，前端暂停播放并请求后端返回对应题目，学习者提交答案后，后端根据SQLite中的标准答案完成判定，并生成反馈返回前端。当学习者在聊天窗口中发起问题时，前端会同时提交当前视频名称、播放时间和历史对话；后端先根据播放时间构造局部时间窗上下文，再结合向量库召回的相关课程片段和补充资料，组织提示词并调用大模型生成回答，最终将回答内容及引用依据返回页面。

通过上述流程，离线阶段负责“把课程内容加工成知识资源”，在线阶段负责“根据学习情境调用知识资源”。二者之间以结构化数据库和向量检索库为中间载体，既降低了在线响应压力，也保证了问答和测验结果能够与具体视频片段、知识点和时间位置建立关联。

综上，本章围绕在线视频课程智能助教系统给出了总体设计方案。系统以本地课程视频为核心输入，通过前端交互层、后端服务层、离线知识构建层和数据存储与检索层协同工作，实现了从视频多模态处理、知识点与题库生成、向量化检索到在线问答和测验反馈的完整链路。相比仅基于文本资料的问答系统，本系统在设计上引入了视频播放时间、字幕语义、视觉语义、历史对话和补充资料等多源上下文，使问答和反馈能够更贴合学习者当前所处的课程场景。下一章将在该总体架构基础上，进一步说明开发环境、技术选型以及各功能模块的具体实现方法。

4.1  开发环境与技术选型
本系统面向本地在线视频学习与智能助教场景，既需要完成视频转写、视觉解析、知识点提炼、题库生成和向量化入库等离线处理任务，也需要在学习者观看视频时提供稳定的问答、测验和反馈服务。因此，系统在技术选型上采用“前后端分离、离线在线分流、本地数据存储、外部模型能力调用”的实现思路。该方案能够降低系统部署复杂度，同时将计算密集型任务与实时交互任务分离，保证在线学习过程的响应稳定性。

系统整体不进行大模型训练或参数微调，而是通过语音识别模型、视觉语言模型、嵌入模型和OpenAI兼容的大模型接口完成语音转写、视觉理解、知识提炼、答题评估和问答生成。前端负责学习界面与交互状态管理，后端负责接口服务、数据库访问、检索编排和模型调用，离线脚本负责知识库和题库构建。各类技术组件的选择均围绕“本地可运行、模块易替换、数据可沉淀、交互可响应”展开。

4.1.1  开发与运行环境

系统主要目录和配置项通过环境变量管理，包括课程视频目录、字幕目录、补充资料目录、SQLite数据库路径、Chroma向量库路径、嵌入模型路径、Whisper模型路径、大模型接口地址和模型名称等。通过集中配置，系统在更换模型、调整数据目录或修改服务端口时不需要大规模改动代码，有利于后续维护和迁移。

在运行资源安排上，系统将耗时较高的任务放入离线流水线，例如语音转写、关键帧提取、视觉语言模型解析、知识点提炼、题库生成和向量化入库；在线服务阶段仅保留视频资源查询、题目查询、答题评估、向量检索和回答生成等与交互直接相关的任务。该方式能够减少用户观看视频或提问时的等待时间，提高在线交互的稳定性。系统开发环境与关键技术选型如表4.1所示。

4.1.2  技术选型依据
（1）前端框架选型。在线视频学习界面需要同时处理视频播放进度、课程切换、题目触发状态、弹窗作答、聊天消息和历史对话等多种状态。Vue3具备响应式数据绑定和组件化开发特点，能够较自然地将播放状态、测验状态和问答状态组织在同一页面中；TailwindCSS则便于快速构建清晰的学习界面布局。因此，前端采用Vue3和TailwindCSS实现视频学习区、随堂测验区和智能问答区的交互展示。

（2）后端框架选型。系统后端需要提供视频列表获取、课程元数据查询、题目拉取、答题评估、RAG问答、视频重建和流水线执行等接口。FastAPI支持基于Pydantic的数据结构校验，能够规范前端提交的问题、播放时间、历史对话和答题内容等参数；同时，FastAPI接口定义清晰，便于将不同功能拆分为独立路由。Uvicorn作为ASGI服务器，能够满足本地服务启动和调试需求。因此，后端采用FastAPI和Uvicorn实现REST API服务。

（3）结构化存储选型。随堂测验题目、选项、标准答案、知识点、视频名称和触发时间戳具有明显结构化特征，需要支持按视频名称和播放时间进行快速查询。SQLite无需单独部署数据库服务，数据文件易于备份和迁移，适合本系统单机运行和本地演示的使用场景。因此，系统采用SQLite保存题库与知识点等结构化数据。

（4）语义检索选型。课程字幕、多模态时间线片段和补充资料属于非结构化文本，仅依靠关键词匹配难以准确召回与学习者问题语义相关的内容。系统采用BGE Embeddings将课程文本和补充资料转换为向量表示，并使用Chroma进行本地持久化存储和相似度检索。在问答阶段，后端根据学习者问题召回相关课程片段和扩展资料，再与当前视频时间窗上下文共同组成提示词，实现检索增强生成。

（5）语音与视觉处理选型。课程视频同时包含语音讲解、屏幕文字、图表、公式和示例画面。为完整获取课程知识，系统使用Faster-Whisper完成音频转写，生成带时间信息的字幕片段；使用OpenCV从视频中抽取关键帧；再调用视觉语言模型识别关键帧中的文字、公式、图表和视觉语义。上述结果经过时间轴融合后，可形成比单纯字幕更完整的多模态课程知识片段。

（6）大模型调用方式选型。系统中的知识点提炼、题目生成、答题反馈、问答生成和补充资料总结均需要较强的自然语言理解与生成能力。考虑到毕业设计周期、硬件资源和训练成本限制，系统不进行本地模型训练或微调，而是通过OpenAI兼容API调用预训练模型。该方式能够降低实现复杂度，并使聊天模型、评估模型、题目生成模型和视觉语言模型可以通过配置项灵活替换。

4.1.3  工程化实现策略
为提高系统的可维护性和运行稳定性，本文在实现过程中采用以下工程化策略：

（1）离线在线分流。系统将视频转写、关键帧解析、多模态融合、题库生成、Web补充资料生成和向量化入库放入离线流水线执行；在线阶段主要负责接收前端请求、查询数据库、执行向量检索、组织上下文并调用模型生成结果。该策略避免了高耗时任务阻塞学习者的实时交互过程。

（2）模块化组织。系统按照前端页面、后端接口、离线脚本、数据库和向量库进行模块划分。前端主要维护用户交互状态，后端统一暴露REST API，离线脚本分别承担转写、视觉解析、融合、知识提炼和入库任务。模块之间通过标准化文件、数据库记录和接口参数衔接，便于单独调试和后续扩展。

（3）增量处理机制。系统的视频资源、字幕文件、视觉描述、补充资料和向量库均以本地目录或持久化数据库形式保存。当新增课程视频或补充资料时，可以只对新增内容执行处理和入库，减少重复计算，提高数据构建效率。

（4）统一配置管理。系统通过环境变量集中管理视频目录、数据库路径、向量库路径、模型路径、API地址、模型名称、服务端口和跨域参数等配置。该方式降低了硬编码带来的维护成本，也方便在不同设备或不同模型服务之间迁移。

（5）结果持久化与可追溯。离线处理结果会保存为字幕文件、多模态时间线文件、视觉描述文件、SQLite题库记录、Chroma向量索引和补充资料文档。通过保存中间结果，系统能够在出现错误时定位具体处理阶段，也便于后续论文实验部分统计题库数量、知识点覆盖和检索效果。

上述技术选型与工程策略共同支撑了系统在本地环境下的稳定运行，并为后续模块实现、功能测试和实验评测提供了基础。

4.1.4  小结
本节从开发与运行环境、核心技术选型和工程化实现策略三个方面说明了系统实现基础。整体来看，Vue3与FastAPI支撑了前后端分离的在线交互，SQLite与Chroma分别承担结构化数据管理和语义检索任务，Faster-Whisper、OpenCV、视觉语言模型和嵌入模型支撑了离线多模态知识构建，OpenAI兼容API则提供问答、评估和知识生成能力。通过上述组合，系统能够在不训练新模型的前提下，实现面向课程视频学习场景的随堂测验、上下文感知问答和补充资料扩展功能。下一节将进一步介绍离线多模态知识构建模块的具体设计与实现。
